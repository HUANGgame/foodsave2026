# App→真Azure：最小待確認驗收與交付

2026-10-03：SQL rollback15項、SQL雙連線並發3項與精確QA清理已由部署端確認通過；Android extended fixture run37104919923成功。尚無同一次「已安裝APK→真HTTPS API→真SQL」完整證據。這份文件是下一輪方案，**未執行、未授權建立新帳號或新QA批次**。

## 最小測試範圍

1. **先確認既有允許通路。** 部署負責人私下確認核准API URL及可用測試装置／環境。若browser URL policy拒絕，停止該通路並記錄阻擋，交由使用者／管理方處理；不得換IP、代理、轉址、改DNS或改用其他工具繞過同一拒絕。裝置上的人工測試也須有獨立核准的正常存取通路，不視為政策繞過方案。
2. **一次真API debug APK。** 範圍批准後，以既有live模式與核准HTTPS API重新build及cap sync，使用debug signing；保留測試package，不索取release金鑰、不嵌入帳密、不開release除錯。核對產物中的API設定、manifest、大小、SHA256及簽章。CI fixture包不可當作真API包交付。公開repo／CI日誌不放實際資源URL、帳號或私密測試資料。
3. **先做非寫入門檻。** 在安裝的APK檢查登入頁與API可達性；由已核准部署通路確認health/live、health/ready及privacy回應，不以health成功替代App成功。真正WebView來源預期為https://localhost，檢查現有CORS是否已明確允許；若不允許，列出精確變更待批准，不能放寬到星號、停用TLS或改cleartext。
4. **最小核心閉環：2個帳號、1店、1商品。** 優先使用營運者明確指定的測試帳號；否則另批批准一個consumer、一個vendor，僅在批准後建立。指定1份synthetic商品，由商家App表單新增，consumer登入後從真API看到該商品、預約成功、讀取本人訂單，vendor讀到同一筆。consumer取消後庫存回到1，vendor重新載入同樣結果；再次取消／相同key重試不重複返還。登出／force-stop後回到登入，重新登入仍讀到已取消狀態。取貨碼、密碼與bearer不寫公開日誌。
5. **證據與收尾。** 同一版本記錄裝置／Android版本、App畫面、實際HTTP狀態及去敏請求識別、owner只讀SQL不變量（1筆取消訂單、stock1、無重複結果）。公開僅記錄斷言與摘要；私有證據依批准期限處理。測試前必須先確認該新scope的preview/apply清理方式；既有owner_cleanup.py只接受waiting狀態及qa-concurrent-stock，**不能清理本方案的已取消訂單或商家上架等額外結果**。不要為了清理成功放寬該工具。

最小閉環不包含新admin帳號、抽獎授次／真獎品、EXP設定、公開註冊、永久刪除或新權限。若要核銷／評論／收藏／抽獎等完整驗收，另列所需資料、操作與清理範圍；不能將本輪兩帳號閉環稱為所有功能通過。
