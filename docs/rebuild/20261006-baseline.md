## 已核對的落差與分批重建範圍

1. 基線 `backend/foodsave/service.py` 的商品和店家查詢仍使用全域 `FETCH NEXT 200 ROWS ONLY`；`admin.py` 的商家商品也限制 200。需先依後端距離 1 公里篩選，再以穩定且唯一的排序鍵分頁；涵蓋大於 200 筆、邊界、同距離及翻頁測試。前端可見時每 30 秒刷新並避免競態覆寫。
2. 重建同一永久 user ID 同時為顧客與商家、按鈕「我要上架」、一人一店。保留 admin 及舊 session，不改用重新註冊或批次角色覆寫。以交易與唯一限制保護跨店操作及同時建立店家。
3. 預約、核銷及獎勵流程都驗證本人與店主關係，禁止自領及重播獎勵；驗證併發、過期、重試與跨店請求。不能只加前端按鈕判斷。
4. 公開店址先用 GPS 草稿，拖曳後確認保存。存在待領或過期未結算訂單時禁止移動；移動及下單共用合適鎖定，訂單保存取貨點快照。
5. 舊 013 含清除 session／owner 綁定風險（交接資訊）；不可直接執行。取得內容後隔離審查，再形成保留 session/admin 的獨立 migration 與索引修正。先在既有免費 validation 庫執行真實 SQL 整合、競態與回復驗證，再安排正式更新。不以舊模擬結果當作此次通過。
6. 取得 0.4.10 資產後逐项核對並重建地圖、搜尋、青蛙定位、跟隨、聚合及 Google 導航，保留簡潔介面；編譯資產不冒充完整原始碼。
7. 網站與 Android APK 必須使用同一後端、帳號及功能。APK 核對 applicationId、versionCode 遞增、舊版簽章相容性、權限、打包資產與 API 設定；build 通過不等於真機觸控通過。
